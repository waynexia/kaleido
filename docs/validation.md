## 复现早期共存验收

以下驱动依赖 AltTab 和共存方案，仅用于明确需要的并排比较。当前日常使用仅运行 Kaleido，不应为常规检查自动启动 AltTab 或覆盖标准方案。

先退出正在运行的 Kaleido 和旧 Window Fixture，保留 AltTab。驱动会检查 AltTab 能否通过 Control + Tab 唤出，因此需要保持该参照快捷键配置。使用 Debug 构建：

```sh
CONFIGURATION=debug make check
```

确认当前 `build/Kaleido.app` 的辅助功能授权有效；如为检查状态而打开过应用，开始测试前先退出，避免 `open --args` 复用已有进程而未启动驱动。随后运行：

```sh
./scripts/fixture.sh
open build/Kaleido.app --args --coexist --integration-check "$PWD/build/integration-report.json"
```

这是显式启用的 Debug 集成测试，会短暂发送全局按键并改变测试窗口。运行期间不要同时操作键盘。成功后退出测试应用，Kaleido 继续后台运行。报告的 `status` 为 `passed` 或 `failed`；测试不会修改 AltTab 配置。

添加 `--capture-kaleido` 或 `--capture-reference` 可让驱动分别在面板可见时暂停最多 45 秒。报告状态为 `kaleido-visible` 或 `reference-visible`，检查完后创建 `<报告路径>.kaleido-continue` 或 `<报告路径>.continue` 继续；再次使用前删除旧的继续标记。

默认使用固定证书签名，正常构建更新继续使用既有授权。从旧 ad-hoc 身份迁移时，必要时从辅助功能列表移除旧条目，添加当前应用并重启。通过 `open` / LaunchServices 启动；直接运行可执行文件的 `--diagnose` 仅描述该命令进程的权限上下文，不能代表已启动的应用。
